## 🧠 Context to carry forward

**Why comparator was thought hard, and why it isn't (the key finding):** comparator does NOT hardcode a Mathlib-only environment. It builds the Challenge against **the repo's own `lakefile`** (README assumption #1; `runtests.lean` uses the project lakefile if present; `config.json` has no deps field). g-i's lakefile already `require`s Foundation, so a Challenge that does `import Mathlib` + `import Foundation…` builds and compares fine. "Mathlib-only" is a **trust-minimization convention, not a tool constraint**. The real cost is (a) trust base grows Mathlib→Mathlib+Foundation (a one-line honest decision; Flypitch CH-independence sits on 1000.yaml on the same basis), and (b) the faithfulness re-declaration of `goodsteinSentence`'s closure.

**Correction made mid-session (important, don't regress):** I initially claimed the semantic bridge `goodsteinSentence_faithful : (ℕ ⊧ₘ goodsteinSentence) ↔ ∀ m,∃N, goodsteinSeq m N = 0` lets us leave `igoodsteinDef` as a `definition_names` hole ("fidelity certified, not eyeballed"). **That's wrong.** The bridge's RHS (Goodstein terminates) is a *proved theorem*, so the iff **collapses to just `ℕ ⊧ₘ goodsteinSentence`** — satisfiable by *any* ℕ-true, PA-unprovable `∀∃`-sentence. So a def-hole on `igoodsteinDef` would be **gameable** (exactly what the "never use def holes" doctrine warns about, and it's right here). ⇒ The Challenge **must re-declare `igoodsteinDef`'s definitional closure byte-identically.** The bridge is still worth including as an anti-vacuity / ℕ-truth anchor (ties the sentence to the small auditable `goodsteinSeq`), just not a shortcut.

**Scope of the re-declaration (smaller than it looks):** comparator needs only the **definitional** closure (the `def`/`instance` bodies `igoodsteinDef` transitively references), NOT the property-lemmas. `goodstein.construction` + the `𝚺₁-Function` arithmetization machinery are almost certainly **Foundation** (trusted, not copied); only the dev's Goodstein-specific specialization gets re-declared. Real size is unknown from line counts → **enumerate it empirically** by running the local probe and reading its missing/mismatched-constant errors.

**Design for the Goodstein entry:** `theorem_names = [GoodsteinPA.peano_not_proves_goodstein, GoodsteinPA.goodsteinSentence_faithful]`; `permitted_axioms = [propext, Quot.sound, Classical.choice]`; `enable_nanoda: true`. Human-audit surface stays small: re-declare `bump`/`goodsteinSeq` (Mathlib-native) in full for the human to read; the bridge ties `goodsteinSentence` to them.
